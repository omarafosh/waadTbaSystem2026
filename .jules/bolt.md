## 2024-05-01 - [Resolve Full Table InMemory Filtering in Role Management]
**Learning:** `findAll().stream().filter(...)` was used for checking Role assignments and counts in `RoleManagementService` and `RbacGuardService`. Specifically, `getAllRoles()` iterated over every role, calling a method that executed a full table scan of users, creating an O(N*M) performance and memory bottleneck. Moving this into targeted `@Query` methods (`countByRolesId`, `findUsernamesByRolesId`) directly utilizing database JOINs removes massive memory allocation entirely.
**Action:** When filtering relations or aggregating counts based on a collection element (like finding users who have a specific role), never use `findAll().stream().filter()`. Push the logic to the database using JPQL `JOIN` and aggregation functions like `COUNT()`.
