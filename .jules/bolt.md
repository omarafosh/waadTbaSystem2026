## 2024-11-13 - Memory Load for Role Counts via findAll().stream()
**Learning:** `RoleManagementService.getAllRoles()` iterated over every role and called `countUsersWithRole(roleId)`, which executed `userRepository.findAll().stream().filter(...)` for *each* role. For $R$ roles and $U$ users, this fetched the entire user table $R$ times, leading to massive memory overhead and $O(R \cdot U)$ complexity in Java memory. This bottleneck was a severe codebase-specific anti-pattern where filtering was being handled entirely by application memory streams rather than pushed to the database.
**Action:** Replaced `findAll().stream().filter(...).count()` with a targeted JPQL count query `countByRolesId`, and similarly optimized `getUsersWithRole` using `findUsernamesByRolesId`, eliminating the full-table loading loop entirely.
