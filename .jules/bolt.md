## 2024-06-12 - [RoleManagementService Optimization]
**Learning:** In Spring Data JPA, when mapping DTOs that require nested counts (like the number of users per role), replacing iterative `userRepository.findAll().stream().filter(...)` logic with a single `@Query` using `GROUP BY` and an `IN` clause (e.g., `countUsersByRoleIds`) prevents catastrophic N+1 database queries and full-table application memory loads. This is a critical pattern when the mapping relationship is unidirectional (User -> Role) but the count needs to be aggregated from the inverse side.
**Action:** When implementing DTO mappings that require aggregate statistics of unmapped inverse relationships, implement custom JPQL queries in the repository to compute these statistics in batch, returning `List<Object[]>`, and map them via an in-memory `Map` lookup before the primary mapping loop.
