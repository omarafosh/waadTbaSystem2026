## 2026-05-23 - Prevent O(N) full-table in-memory filtering in RoleManagementService
**Learning:** Found an inefficient pattern where the entire user table was loaded into memory via `userRepository.findAll().stream()` to filter users by role and count users with a specific role. This is a severe O(N) memory and I/O bottleneck in Spring Data JPA when dealing with large datasets.
**Action:** Replaced `findAll().stream()` with targeted JPQL projections (`@Query("SELECT u.username FROM User u JOIN u.roles r WHERE r.id = :roleId")`) and count queries (`@Query("SELECT COUNT(u) FROM User u JOIN u.roles r WHERE r.id = :roleId")`) to push the filtering directly to the database. Also used `existsById` to efficiently validate role existence. Added inline comments to explain the performance impact.
