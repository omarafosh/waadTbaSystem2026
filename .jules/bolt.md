## 2026-01-26 - Resolved Full-Table In-Memory Filtering Bottleneck in PreAuthorizationService.checkValidity
**Learning:** Found a full-table in-memory filtering scan in `PreAuthorizationService.checkValidity` via `findAll().stream().filter(...)` that was causing severe O(N) performance degradation as the PreAuthorization table grows. The logic fetched the entire table into memory just to find the most recent valid pre-authorization for a given member and service code.
**Action:** Created a targeted JPQL query `findFirstValidPreAuth` in `PreAuthorizationRepository` with an `ORDER BY pa.createdAt DESC` and date checks, pushing the filtering and sorting directly to the database. This resolves the bottleneck and replaces it with an efficient O(1) database lookup using indexes.
