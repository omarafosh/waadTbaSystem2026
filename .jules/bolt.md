
## 2026-03-01 - JPQL Refactoring and Inner vs Left Joins in Count Queries
**Learning:** When refactoring a native query to JPQL with `countQuery`, referencing joined entities in the `WHERE` clause (e.g., `v.member.fullName`) implicitly causes Hibernate to generate an `INNER JOIN` in the SQL, potentially causing a mismatch with the main query that uses `LEFT JOIN FETCH`. If the relationship is optional, records will be incorrectly filtered from the count. This was mitigated by explicitly adding `LEFT JOIN v.member m` in the `countQuery`. Additionally, property-based `Pageable` sorting only works reliably when the JPQL uses the entity's property names, rather than native SQL column names.
**Action:** Always explicitly declare `LEFT JOIN` in `countQuery` statements if the main query relies on `LEFT JOIN FETCH` and filters on those joined entities. Also, align JPQL property access paths carefully to match the entity definition, especially when replacing complex native queries.
