## 2026-06-30 - Resolved Full-Table Scan and N+1 in RoleManagementService
**Learning:** `RoleManagementService` had full-table scans and N+1 query bottlenecks in `getUsersWithRole`, `countUsersWithRole`, `getAllRoles`, and `searchRoles` due to iterating over `userRepository.findAll().stream()`. Because the User -> Role relationship is unidirectional (Role does not have a mapped users collection), JPQL queries must drive from the User entity.
**Action:** Created targeted JPQL queries in `UserRepository` (`countByRolesId`, `findUsernamesByRolesId`, and a bulk counting query `countUsersByRoleIds` using `GROUP BY r.id`) to push projection and aggregate counting directly to the database. Refactored `RoleManagementService` to utilize these queries, resolving the performance bottlenecks.
