## 2026-03-21 - [ProviderContractService Batching & ClaimMapper Optimization]
**Learning:** [When attempting to fix N+1 loops, ensuring proper implementations for underlying batch-fetch helper functions is critical. Modifying service APIs requires updating the implementations as well, not just using new dummy batch APIs. Also, always ensure the method definitions are accurately mapped and do not hallucinate simple method names (like `findByCodes` vs `findByCodeIn`) in Spring Data JPA repositories without verifying their existence.]
**Action:** [Always carefully define and implement the specific batch fetching code in the Service or Repository level before modifying callers (like `ClaimMapper`). Avoid assuming standard Spring JPA method signatures; explicitly verify repository methods exist or create them.]
