## 2026-06-22 - Replaced PreAuthorizationService memory scan with targeted JPQL query
**Learning:** The method `checkValidity` in `PreAuthorizationService` loaded the entire `PreAuthorization` table into memory using `findAll().stream()` to filter by member, service, and validity (expiry date, active, approved). This caused extreme N+1 and O(N) memory issues. Additionally, an initial patch failed because an `@Query` annotation was incorrectly inserted before another `@Query` method's javadoc, leading to duplicate annotation and derived query generation errors.
**Action:** Replaced the memory scan with `findValidPreAuthorizationsForMemberAndService`, a targeted JPQL query that does all the filtering (including the conditional `expiryDate IS NULL OR expiryDate >= :currentDate`) directly in the database. Ensure any new repository methods with annotations are carefully placed *after* existing method signatures, not between annotations and definitions.
