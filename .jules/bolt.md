## 2026-05-09 - Push Role Relationship In-Memory Filtering to Database
**Learning:** `UserRepository.findAll().stream()` operations inside loops or high-frequency endpoints like `RoleManagementService.getUsersWithRole`, `RoleManagementService.countUsersWithRole`, and `RbacGuardService.validateSuperAdminExists` cause an `O(N)` whole-table memory load for simple projection and counts. Specifically, because the `User` -> `Role` relationship is unidirectional from `User`, counting or filtering users by role requires scanning users.
**Action:** Always replace `repository.findAll().stream().filter(...)` in services with targeted JPQL queries in the repository. Use `COUNT(u)` or projecting specific fields (like `u.username`) to avoid fetching the full `User` entity tree into memory, which avoids massive performance degradation as the database grows.
