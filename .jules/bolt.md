## 2026-03-01 - Batch coverage lookup in BenefitPolicyCoverageService
**Learning:** `BenefitPolicyCoverageService` exhibited an N+1 query problem by resolving coverage rules for each service inside loops in methods like `validateClaimCoverage` and `batchGetCoveragePercents`. This occurred because it repeatedly called `serviceRepository.findById` and `ruleRepository.findBestRuleForService` for every item in a claim.
**Action:** Implemented a new internal `findBestRuleInMemory` method that reproduces the JPQL `ORDER BY` logic with scoring. Pre-fetched all target `MedicalService` entities and all active `BenefitPolicyRule` entities for the policy in one query, removing the bottleneck. Always look out for sequential querying of rules inside batch loops in domain-heavy services.
