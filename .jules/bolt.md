## 2024-XX-XX - PreAuthorizationService N+1 Issue
**Learning:** `mapToResponseDtoLight` in `PreAuthorizationService` triggers an N+1 query issue when iterating over paginated results because it calls `memberRepository.findById()`, `providerRepository.findById()`, and sometimes `medicalServiceRepository.findByCode()` individually for every `PreAuthorization` record in a loop (`preAuths.map(this::mapToResponseDtoLight)`). This creates massive DB load on list pages like the pending inbox.
**Action:** Replace `preAuths.map(this::mapToResponseDtoLight)` with a new batch-fetching method `mapPageToResponseDtoLightBatch(Page<PreAuthorization> page)` that collects all `memberIds` and `providerIds`, fetches them in bulk via an `IN` clause using the repositories, puts them in an in-memory `Map`, and then iterates through the items to create the DTOs without N+1 queries.
