## 2026-04-04 - [RoleManagementService Query Optimization]
**Learning:** Found a full-table in-memory filtering bottleneck in `RoleManagementService.getUsersWithRole` and `RoleManagementService.countUsersWithRole`. The service was using `userRepository.findAll().stream().filter(...)` to iterate through all users in the application to find roles. This causes an O(N) memory load which is devastating on large databases.
**Action:** Replaced stream filtering with targeted Spring Data JPA database queries (`countByRolesId`, `findUsernamesByRolesId`) directly in the `UserRepository` to leverage database optimization and push the compute off the Java memory heap. Future occurrences of in-memory `.findAll().stream().filter()` should be treated as anti-patterns and fixed using the same approach.
