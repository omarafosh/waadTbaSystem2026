
## 2026-07-02 - RoleManagementService Full-Table Scan & N+1 Bottleneck Resolution
**Learning:** `RoleManagementService` suffered from a major memory and N+1 query bottleneck because `countUsersWithRole(roleId)` and `getUsersWithRole(roleId)` loaded the entire user table (`userRepository.findAll().stream()`) just to perform in-memory filtering by `role.getRoles().contains(role)`. This same bottleneck caused an N+1 issue inside mapping loops (`getAllRoles`, `searchRoles`) where `toViewDto` iteratively called the slow `countUsersWithRole`. In Spring Data JPA where the Role->User collection is not explicitly mapped for lazy loading, we must project using the owning entity.
**Action:** Replaced the full-table `.stream()` logic with efficient database projections and aggregates (`countByRoleId`, `findUsernamesByRoleId`). For batch operations (`getAllRoles`, `searchRoles`), created a `toViewDtos` method and a `GROUP BY` bulk query (`countUsersByRoleIds`) to load all user counts for all requested roles in a single database round-trip, preventing N+1 queries.
