## 2025-03-06 - Prevent In-Memory Filtering on Whole Tables in Services
**Learning:** Found a severe performance bottleneck where `PreAuthorizationService.checkValidity()` was calling `preAuthorizationRepository.findAll().stream()` to perform in-memory filtering for `memberId`, `serviceCode`, and status. This forced an O(N) whole-table load and instantiation, leading to massive memory bloat and slow response times, completely ignoring DB indexes.
**Action:** Always replace `.findAll().stream().filter(...)` patterns in service layers with targeted JPQL queries that utilize database indexing and ordering. If multiple filter conditions are required, create a specialized repository query like `@Query("SELECT pa FROM PreAuthorization pa WHERE pa.memberId = :memberId AND ...")` to push the computation to the database layer.
