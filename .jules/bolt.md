## 2026-06-10 - Full Table Scans vs Batch Fetching
**Learning:** In Spring Data JPA applications, using `repository.findAll().stream().findFirst()` loads the entire table into JVM memory just to fetch a single record. Furthermore, invoking counting methods like `countUsersWithRole()` inside loops (like DTO mappers) results in an N+1 query pattern where the database is hammered with N separate queries. Both occur simultaneously in `RoleManagementService`.
**Action:** Always prefer DB-backed operations. Use Spring Data derived queries like `findFirstByActiveTrue()` to limit fetched rows to one. To resolve N+1 count queries, implement a bulk JPQL query with a `GROUP BY` clause (e.g., `SELECT r.id, COUNT(u) FROM User u JOIN u.roles r GROUP BY r.id`) to fetch all counts in a single query, map them into a `HashMap` pre-loop, and perform O(1) lookups during mapping.
