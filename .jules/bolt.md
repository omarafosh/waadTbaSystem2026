## 2026-04-25 - Targeted Projection and Aggregation Queries to Resolve N+1 Memory Bottlenecks in RBAC
**Learning:** In the RBAC module, due to the unidirectional User-Role relationship (User defines `roles` but Role lacks a `users` collection), Spring Data JPA cannot derive queries like `findByRoles(...)` directly on the Role repository without an explicit mapping. As a result, code often relies on fetching the entire User table and performing in-memory `.stream().filter(...).count()` or `.map(...)` aggregations, which causes severe N+1 memory bottlenecks and O(N) scaling issues for basic role-counting or permission-fetching operations (e.g., `validateSuperAdminExists`, `generateToken`).
**Action:** When querying unidirectional Many-to-Many or One-to-Many relationships to count objects or fetch single properties (like usernames or permission names), always write targeted, explicit JPQL `@Query` methods on the owning side's repository (e.g., `SELECT COUNT(u) FROM User u JOIN u.roles r WHERE r.name = :roleName`) instead of using `findAll().stream()`.
