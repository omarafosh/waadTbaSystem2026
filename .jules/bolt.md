## 2026-06-23 - UnifiedMemberService Full-Table Scan Optimization
**Learning:** Found an in-memory filtering bottleneck in `UnifiedMemberService.createPrincipalMember` where `organizationRepository.findAll().stream().filter(o -> o.getType() == OrganizationType.EMPLOYER).findFirst()` was used to assign VIP members without an explicit employer. This loads the entire organization table into memory to find a single employer record. Replaced it with the derived query `findFirstByType`, preventing potential OOM issues on large datasets. Also learned that when replacing exception message string assertions in unit tests, verify the actual runtime message thrown in the service to avoid assertions failing due to unexpected prefixes/suffixes.
**Action:** Always favor derived queries like `findFirstBy...` over `findAll().stream().filter(...).findFirst()` when looking for specific conditions. Before creating a PR, check relevant test files and use `grep` to verify matching exception messages.
