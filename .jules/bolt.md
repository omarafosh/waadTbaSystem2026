## 2026-04-21 - [Optimize RbacGuardService validateSuperAdminExists memory bottleneck]
**Learning:** `RbacGuardService.validateSuperAdminExists()` used a full-table fetch `userRepository.findAll().stream()` followed by an in-memory `.filter()` to count `SUPER_ADMIN` users. This is a severe O(N) memory and performance bottleneck on every user modification, which scales poorly as the user base grows. I replaced it with a targeted JPQL count query (`countUsersByRoleName`) in `UserRepository`, moving the aggregation logic to the database (O(1) memory load) and greatly improving performance for authorization checks.
**Action:** When performing aggregate operations (like counting or finding specific related entities) in Spring services, always push the projection logic directly to the database layer via JPQL `@Query` rather than loading all rows into Java memory to use Streams.
