## 2024-07-08 - RoleManagementService Full Table Scans
**Learning:** Found N+1 database queries and full table scans inside `RoleManagementService`. `getUsersWithRole`, `countUsersWithRole`, `getAllRoles`, and `searchRoles` all relied on `userRepository.findAll().stream().filter(...)` resulting in massive memory overhead for checking assigned users. In RBAC modules where User -> Role is mapped but Role -> User is not explicitly mapped as a collection, avoid using iterative count queries inside mapping loops.
**Action:** Use targeted JPQL `@Query` methods (e.g., `countByRolesId`, `findUsernamesByRolesId`) to push projection and aggregate counting directly to the database. For bulk endpoints like `getAllRoles`, use bulk JPA queries (`countUsersByRoleIds` using `GROUP BY r.id`) and map the results in memory to eliminate N+1 bottlenecks.
