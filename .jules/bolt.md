## 2026-03-30 - Optimize Role and User findAll mapping by preventing N+1 queries
**Learning:** Returning `List<Entity>` directly via `repository.findAll().stream().map(...)` in Spring Data JPA results in catastrophic N+1 query proliferation if the DTO mapping invokes getter methods on lazily-loaded one-to-many or many-to-many relationships (e.g., `User.roles`, `User.permittedOrganizations`, `Role.permissions`). Unlike targeted paginated endpoints, simple `findAll()` mapping can execute thousands of redundant single queries to resolve these proxies. While `UserRepository.findAll()` didn't use any explicit `EntityGraphs` and thus fetched every `Role` and `Organization` one by one, we correctly applied database-level optimization through custom `@Query` definitions with `LEFT JOIN FETCH` (e.g., `findAllWithAssociations()` and `findAllWithPermissions()`) replacing simple `findAll()`.
**Action:** Always prefer defining an explicit repository method containing `LEFT JOIN FETCH` or `@EntityGraph` for any `findAll()` operation that feeds directly into a DTO mapper, ensuring relationships are bulk-loaded in a single query rather than lazily triggered O(N) times during `.map()`.
