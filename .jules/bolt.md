## 2026-01-28 - [Backend/JPA] Push In-Memory Filtering to Database
**Learning:** Found a full-table in-memory filtering bottleneck in `PreAuthorizationService.checkValidity()`. It was using `preAuthorizationRepository.findAll().stream().filter(...)` to find a single valid pre-auth out of the entire table. Since the table grows indefinitely over time, pulling the whole table into memory for standard business logic checks causes severe memory bloating and O(N) performance degradation.
**Action:** When searching for specific active/valid records within a massive dataset based on specific identifiers (like memberId, serviceCode, status, dates), avoid using `findAll().stream().filter()`. Instead, write targeted JPQL `@Query` methods (e.g., `findValidPreAuthorizationsForMemberAndService`) passing the parameters via `@Param`. This pushes the projection, filtering, and sorting down to the database, converting the O(N) full memory load to a rapid O(1) indexed database query.
