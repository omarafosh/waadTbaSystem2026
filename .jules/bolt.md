## 2026-06-03 - Optimize N+1 Query in RoleManagementService countUsersWithRole
**Learning:** In RBAC modules where User -> Role is mapped but Role -> User is not explicitly mapped as a collection, querying role statistics (like `countUsersWithRole`) using `userRepository.findAll().stream().filter(...)` causes an O(N) memory load bottleneck. Fetching this data inside a loop (like `getAllRoles().stream().map(...)`) turns it into an N+1 performance bottleneck. Even when refactored to a targeted JPQL count query (`countUsersByRoleId`), calling it iteratively inside a stream is still an N+1 database bottleneck.
**Action:** Always replace iterative count queries in list mappers with bulk queries (e.g., `countUsersByRoleIds(List<Long> roleIds)` using `GROUP BY r.id`) and map the results in memory to achieve O(1) loop lookups, turning N+1 queries into 2 queries.
