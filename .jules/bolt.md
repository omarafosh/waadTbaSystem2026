## 2024-05-03 - RoleManagementService In-Memory Filtering Bottleneck
**Learning:** Found a severe full-table scan bottleneck in `RoleManagementService` where `getUsersWithRole` and `countUsersWithRole` pulled the entire `users` table into application memory via `userRepository.findAll().stream().filter(...)` just to check role assignments. Since the User-Role relationship is unidirectional from `User` (Role does not have a mapped users collection), querying must be driven from the `User` entity using explicit joins (e.g., `SELECT u FROM User u JOIN u.roles r WHERE r.id = :roleId`).
**Action:** Always replace application-layer stream filtering of standard repository `findAll()` methods with targeted JPQL projections (e.g., `countByRolesId`, `findUsernamesByRolesId`) directly in the database layer, especially for N-to-M relationship checks.
