## 2026-04-14 - [Replace In-Memory Filtering with Database Queries for Roles]
**Learning:** Found critical O(N) memory bottlenecks in `RoleManagementService` and `RbacGuardService` where `userRepository.findAll().stream()` was used to count users by role or map usernames. This required pushing the counting and projection to the database level. Since the `User` -> `Role` relationship is unidirectional, the JPQL queries needed to be driven from the `User` entity (e.g. `SELECT COUNT(u) FROM User u JOIN u.roles r WHERE r.name = 'SUPER_ADMIN'`).
**Action:** In Spring Boot applications using JPA, always inspect list methods doing `.size()` or stream `.count()` for potential refactoring into a database-level `countBy` or `@Query("SELECT COUNT(...) ...")`. For unidirectional relationships, ensure the query originates from the owning entity.
