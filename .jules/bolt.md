## 2026-06-24 - Bulk Group By Queries for Collections
**Learning:** The standard findById() in mapping loops (N+1 database calls) and findAll().stream().filter(...) for filtering data are severe performance anti-patterns in Spring Data JPA applications with heavy DB ties. Often, mapping logic does not require full entities. We can leverage bulk JPQL aggregation queries (e.g. SELECT r.id, COUNT(u) ... GROUP BY r.id) and populate the values into a Map in memory to efficiently execute DTO transformation for lists without making O(N) database queries.
**Action:** When returning Lists of DTOs mapped from full entities, immediately look for hidden N+1s where dependent data is iteratively queried for each entity (like countUsersWithRole for every Role). Optimize by pre-fetching bulk counts/aggregations via grouped queries, placing them in memory maps, and accessing them via O(1) lookups inside mapping lambdas.
