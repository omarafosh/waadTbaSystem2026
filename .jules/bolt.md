## 2026-03-19 - N+1 Query Resolution via Programmatic Batching
**Learning:** Adding `@ManyToOne` with `@NotFound(action = IGNORE)` to legacy entities like `PreAuthorization` (which store foreign keys as raw `Long`s) to try and fix N+1 queries via `LEFT JOIN FETCH` causes unintended side effects. Specifically, Hibernate often disables lazy loading for `@NotFound(action = IGNORE)` properties because it has to verify if the entity actually exists, leading to global eager fetching issues and `LazyInitializationException`s. Furthermore, adding `FETCH` joins to `Pageable` queries without perfectly synchronizing the `countQuery` introduces critical pagination bugs.
**Action:** Always resolve N+1 queries for paginated lists using programmatic batch fetching in the service layer (extracting IDs, batch loading via `IN` clauses, and mapping in-memory O(1)) instead of hacking the Entity or Repository JPQL unless the relationship is natively defined and safe.
