## 2024-03-11 - Optimize N+1 in BenefitPolicyCoverageService batchGetCoveragePercents
**Learning:** Translating canonical rule-precedence logic (service match vs category match, exact encounter type vs fallback) into batch memory-mapped Java logic requires extreme care with nullability. `encounterType.equals(rule.getEncounterType())` will throw an NPE if the `encounterType` parameter is null. Additionally, dynamically collected IDs for `IN` clauses (like `categoryIds`) must be guarded with dummy values (e.g., `-1L`) to prevent SQL syntax errors on empty lists.
**Action:** Always prefer `==` for Enum equality checks to safely handle nulls (`encounterType == rule.getEncounterType()`). Guard dynamic `IN` clause lists with dummy values if they could be empty, and add fast-return logic (`if (serviceIds.isEmpty()) return...`) before DB queries.
