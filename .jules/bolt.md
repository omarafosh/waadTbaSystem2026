## 2024-05-18 - Full Table Load Bottleneck in RoleManagementService Resolved
**Learning:** In Spring Data JPA, mapping nested collections or checking collection relationships iteratively inside a stream (e.g., `userRepository.findAll().stream().filter(user -> user.getRoles().contains(role))`) is a catastrophic performance anti-pattern. It bypasses database indexes, forces the JVM to process millions of records, and compounds into an O(N^2) bottleneck if called within another loop (like `toViewDto` for all roles).
**Action:** Always replace `findAll().stream().filter()` involving relational checks with explicit JPQL queries. When mapping multiple parent entities (like mapping all Roles to DTOs), use `GROUP BY` and an `IN` clause to bulk-fetch the child counts/associations in a single query, then map the results in memory using a `Map`.
