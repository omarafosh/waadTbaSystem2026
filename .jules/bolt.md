## 2026-05-02 - [Fixing Memory and Database Scanning with JPQL in RBAC Guard Service & Role Management Service]
**Learning:** Found an anti-pattern of full-table retrieval mapping loops via `findAll().stream()` for `RoleManagementService.getUsersWithRole`, `RoleManagementService.countUsersWithRole`, and `RbacGuardService.validateSuperAdminExists`. Fetching all entities into memory just to map string lists or verify count sizes leads to an O(N) memory allocation and processing bloat where counting can be natively deferred to the database via explicit `@Query` mappings. In `RoleManagementService`, the issue was extracting `User.getUsername` lists or verifying row counts by retrieving every user into memory.
**Action:** Replaced stream operations with direct explicit `@Query` aggregations returning `long` counts and String lists in `UserRepository` that map to `findUsernamesByRolesId`, `countByRolesId`, and `countByRolesName`.
