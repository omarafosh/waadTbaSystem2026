## 2024-05-18 - Role Management Full-Table Scan Bottleneck
**Learning:** `RoleManagementService` methods like `getUsersWithRole`, `countUsersWithRole`, `getAllRoles`, and `searchRoles` suffered from catastrophic full-table scans because they loaded all users via `userRepository.findAll()` and filtered them by role in memory using streams. Furthermore, the `toViewDto` mapper triggered an N+1 issue for user counts.
**Action:** Replace `findAll().stream().filter(...)` with targeted JPQL queries (`findUsernamesByRolesId`, `countByRolesId`) directly in the `UserRepository`. For batch mapping, implement a `GROUP BY` query (`countUsersByRoleIds`) to load all required counts in a single DB round-trip and pass a pre-computed map down to the mapper logic to eliminate N+1 behavior.
