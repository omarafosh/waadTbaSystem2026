## 2026-05-26 - Optimized Role Management Service via Targeted JPQL
**Learning:** `RoleManagementService` `getUsersWithRole` and `countUsersWithRole` were loading all user entities into memory (`findAll().stream()`) and filtering them in Java. The RBAC entity relationship is unidirectional (`User` has `roles`, but `Role` does not map `users`). By creating specific JPQL queries (`findUsernamesByRolesId`, `countByRolesId`) in `UserRepository`, we pushed the projection and aggregation to the DB, preventing massive memory loads on instances with many users.
**Action:** When finding usernames or counting a subset by a unidirectional `@ManyToMany` mapping like Roles, always drive the query from the entity that owns the relationship (`User`) using `JOIN` in custom JPQL instead of pulling the whole table to memory.
